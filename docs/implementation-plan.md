- **M2-03 — staged file publication and startup reconciliation: done (internal add-as-new-book; no UI).** `src/library/import.ts` adds one PDF/EPUB as a new Unread, unfiled book titled from its file name. It records a pending `recovery_operations` row, streams the source into `staging/<operation>.partial` while hashing, fsyncs, and sniffs the staged bytes (`src/library/formats.ts`: a `%PDF-` header in the first KiB; a ZIP whose central directory lists `META-INF/container.xml` and whose `mimetype`, if present, is `application/epub+zip`), rejecting unsupported or extension-mismatched content. It then records the digest (staged), renames into `files/<revision>.<ext>` without overwriting and fsyncs both directories, records published, and inserts the book and revision and marks the operation committed in one transaction. `src/library/recovery.ts` rolls back any import that did not reach that commit, in process and at startup: it removes only record-named regular files (a pending partial copy, or a complete copy matching the recorded digest) and marks the operation abandoned. Anything else (digest mismatch, a symlink, both paths present, catalog references) is retained and marked failed and is reported at every start. A failed removal leaves the record open for retry. Stray managed files are reported, never deleted. Startup reconciles before the first window, after the content/network handlers are installed. `mise run check` passes with 147 unit cases; 35 are import/recovery cases with real files and child processes killed at each of the six protocol points, plus a kill after commit. `mise run smoke` passes 26 native cases, including a real import killed mid-copy and reconciled by Electron startup; `smoke-packaged` passes 6 and `measure` stays within budget. ## Verification/tooling defaults

- Use pnpm and mise; do not install global project dependencies. Build/install may acquire dependencies; installed application use must work offline.
- Prefer Vitest for focused TypeScript behavior tests and real storage integration tests. Use actual known outcomes and small fixtures; do not copy the implementation's algorithm into an oracle. [Vitest guide](https://vitest.dev/guide/)
- Prefer Playwright for actual Electron smoke flows. Its Electron automation is documented as experimental: confirm compatibility in the spike and record a manual native-app fallback for any unsupported checks. A browser-only demo cannot prove Electron window/persistence/isolation behavior. [Playwright Electron API](https://playwright.dev/docs/api/class-electron)
- Test nondeterministic failures at narrow boundaries; do not mock every service and then claim storage safety. Use actual adapters for rendering/progress checks. Add overlapping tests only for distinct failure modes.
- The runnable scripts are documented in [development setup](development.md): `dev`, `typecheck`, `lint` (including format checks), `format`, `test`, `test:e2e`, `build`, and aggregate `check`. Extend this tooling when actual implementation needs justify it.
- Commit `pnpm-lock.yaml`; clean installs use `pnpm install --frozen-lockfile`. Enforce minimum release age and named lifecycle-script allowances from AGENTS.md. Check clean packaged execution, not only a hot-reload session.

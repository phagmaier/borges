## Current task

- **M1-07 — packaged runtime/resource measurements: done (diagnostic books; catalog measurements pending milestone two).** `mise run measure` relocates the packaged artifact onto the home HDD. It substitutes a generated 400-page/211k-word PDF and a 40-chapter/120k-word EPUB for the allowlisted fixture bytes in that copy, then measures warm, page-cache-evicted and first-run launches; two open readers; page turns; full-book search; PSS memory; renderer disposal; and five open/close cycles. Budgets at about 2–3× the worst of eight runs are enforced with soft assertions, and a deliberately violated budget fails. Findings: both readers' content frames share one renderer process, which affects crash/memory containment. Main-process native memory grows about 5 MiB per two-reader cycle but was reclaimed in both instrumented and uninstrumented runs. A full 400-page PDF scan takes about 0.85 s. `mise run check` passes with 44 unit cases. See [M1-07 evidence](development.md#packaged-runtimeresource-measurements-m1-07). Not covered: catalog search, the 500-entry catalog (A13), a post-boot cold cache, other scales/backends/GPUs.

Built-in `node:sqlite` persists a known Unicode marker/count across real process restarts. Future/damaged schemas fail startup while preserving database bytes. `mise run check` passes with 44 unit cases; three packaged cases pass; serial full smoke has 23 passing cases and the unchanged M1-02 focus failure. - Evidence (2026-11-03): `mise run check` passes (TypeScript, Biome, 13 unit cases, production build). `mise run smoke`: five native cases pass; the existing-reader focus case fails. Direct requirements/code/test review found no other unresolved in-scope defect. Reader shells retain sandbox/context isolation and deny Node access.
- Resolution (2026-11-03): **this is a narrowed requirement, not a disabled test.** The default launch was already native Wayland. A reopen triggered by a compositor-delivered key event sends an xdg-activation request, and Hyprland with `misc:focus_on_activate = false` turns it into an `urgent` event, not focus. The user rejected changing Hyprland configuration and class-scoped activation rules. The spec and A5 now require reopening to reuse the existing reader window and request activation; where the compositor denies it, one click brings it forward. The native test still asserts window reuse, initial focus/loss, visibility and exactly one activation request. Only the reopen `isFocused()` assertion was removed, and a mutation that drops the request fails the test. Second-launch activation of an already-open library was narrowed the same way and has its own native case. `mise run smoke`: 25 of 25 pass. See [focus evidence](development.md#multi-window-spike-m1-02).
- **M2-01 — catalog schema, migrations and library-root lock: done.** The diagnostic runtime database is replaced by the versioned catalog (`src/storage/`): schema 1 has book/revision/metadata provenance/author/subject/section/membership/position/reader-settings/Trash/recovery-operation/library-identity tables, root-relative path checks, and invariants enforced in SQLite (current revision belongs to its book, format-matched positions, sibling-name uniqueness, cycle rejection, branch deletion that keeps books). Forward-only migrations run in one transaction with a verified pre-upgrade `VACUUM INTO` snapshot in `recovery/`; newer, foreign, unreadable and damaged catalogs are refused before any write. The exclusive root lock is a kernel-released SQLite file lock, so stale recovery needs no PID guessing. Packaged builds default to `$XDG_DATA_HOME/borges/library` (else `~/.local/share/…`), `BORGES_LIBRARY_ROOT` sets an explicit absolute root, and unpackaged development builds use `<profile>/library`. `mise run check` passes with 87 unit cases, including real child processes for cross-process lock and kill-during-upgrade recovery. `mise run smoke` passes 25 native cases, `mise run smoke-packaged` 5 packaged cases (restarts, moved root, second-profile lock conflict, SIGKILL recovery, three refusals), and `mise run measure` stays within budget. See [M2-01 evidence](development.md#catalog-schema-migrations-and-root-lock-m2-01). Not covered: library/progress services, file publication, GUI presentation of startup refusals (they print to stderr and exit 1; show them in the window when the library UI arrives in milestone three, and at the latest in milestone-six launcher work), and A13 catalog measurements.
- **Next ready: M2-02 — central progress/settings storage with session ownership.** Before any privileged progress endpoint exists, add the coordinator-side session record (book ID, revision ID, session generation, monotonic sequence) and catalog writes for positions/reader settings. Reject wrong-sender, wrong-book/revision, retired-generation and reordered writes against actual committed storage, and acknowledge saves or report failures. Milestone one's remaining open item is still the catalog/A13 measurement.

## Verification/tooling defaults

- Use pnpm and mise; do not install global project dependencies. Build/install may acquire dependencies; installed application use must work offline.
- Prefer Vitest for focused TypeScript behavior tests and real storage integration tests. Use actual known outcomes and small fixtures; do not copy the implementation's algorithm into an oracle. [Vitest guide](https://vitest.dev/guide/)
- Prefer Playwright for actual Electron smoke flows. Its Electron automation is documented as experimental: confirm compatibility in the spike and record a manual native-app fallback for any unsupported checks. A browser-only demo cannot prove Electron window/persistence/isolation behavior. [Playwright Electron API](https://playwright.dev/docs/api/class-electron)
- Test nondeterministic failures at narrow boundaries; do not mock every service and then claim storage safety. Use actual adapters for rendering/progress checks. Add overlapping tests only for distinct failure modes.
- The runnable scripts are documented in [development setup](development.md): `dev`, `typecheck`, `lint` (including format checks), `format`, `test`, `test:e2e`, `build`, and aggregate `check`. Extend this tooling when actual implementation needs justify it.
- Commit `pnpm-lock.yaml`; clean installs use `pnpm install --frozen-lockfile`. Enforce minimum release age and named lifecycle-script allowances from AGENTS.md. Check clean packaged execution, not only a hot-reload session.
